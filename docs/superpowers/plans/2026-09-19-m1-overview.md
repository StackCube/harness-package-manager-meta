# M1: the walking skeleton — overview

M1 proves the model end to end for one package with no dependencies and plain files: publish from a directory, install, detect a hand edit, refuse to overwrite it. Design: `../specs/2026-09-19-iteration-1-technical-design.md`, the M1 row of §8.

It is delivered as three plans. Each ends in something that can be tested on its own, and each is executed and reviewed separately.

| Part | Plan | Repos | Delivers | Needs |
|---|---|---|---|---|
| A | [Contract v0.3 and the archive format](2026-09-19-m1a-contract-and-archive.md) | contract, cli, registry | The M0 carry-over cleared (contract v0.3.0). The Go packer that is the reference for `spec/archive.md`. Golden archive vectors (contract v0.4.0). | M0 merged |
| B | [Registry walking skeleton](2026-09-19-m1b-registry-skeleton.md) | registry | Identity middleware with no bypass, the four `/v1` routes, publish with the core checks in the contract's order, D1 and R2 behind `src/store`, every archive vector passing inside `workerd`. | A merged |
| C | [CLI walking skeleton and end to end](2026-09-19-m1c-cli-skeleton-and-e2e.md) | cli, meta | `init`, `publish`, `add`, `install`, `status` on plan-then-apply. The Claude Code adapter's forward mapping. A fake Access proxy and an end-to-end test against the real Worker. M1's decisions written back to the spec and the PRD. | A and B merged |

B and C's first five tasks do not depend on each other, so they can overlap once A is in. C's end-to-end task needs B.

## What M1 deliberately leaves out

| Left out | Arrives in |
|---|---|
| `hpm login` and the Pulumi deploy | M2 |
| Dependencies, meta packages, `update`, `.hpm/` metadata, `search`, `info`, `new`, `version`; the changelog, trigger and `HPM-TODO` publish checks; the prerelease filter on top of Masterminds/semver | M3 |
| Merge files: `CLAUDE.md` blocks, `settings.json` and `.mcp.json` entries | M4 |
| Publishing a package from a project tree | M5 |
| Adopt | M6 |

A package that needs one of these is refused with a message that names the milestone.

## Decisions M1 makes that the design did not

- **Vectors pin the uncompressed tar, not the gzip bytes.** DEFLATE output legitimately differs between implementations, so a gzip hash would tie the contract to one compressor.
- **A packer emits no directory entries**, writes a fixed gzip header and uses ustar only.
- **`archive_too_large` also covers 64 MB uncompressed**, so a small body cannot expand without limit inside the Worker.
- **The R2 key carries the archive's hash.** Two racing publishes of one version then write different objects, and the row that wins points at its own bytes.
- **`AUTH_JWKS_JSON`** is accepted as an alternative to a JWKS URL. It is the same verification with keys from configuration, and it is how tests supply a key without a bypass.
- **The lockfile passes through members it does not model**, so an older `hpm` never drops what a newer one wrote.

Part C's last task writes these into the design spec and the PRD.
